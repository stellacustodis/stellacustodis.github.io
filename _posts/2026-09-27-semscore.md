## 세 줄 요약

- SEMSCORE는 모델 응답과 사람이 작성하거나 검토한 정답 응답을 문장 임베딩으로 바꾸고, 두 벡터의 코사인 유사도로 응답을 평가한다.
- 논문의 12개 모델 비교에서 SEMSCORE는 인간 평가와 가장 높은 모델별 상관을 보였다. 보고된 켄달 상관의 절댓값은 0.879, 피어슨 상관의 절댓값은 0.970이다.
- 이 결과는 모델별 평균을 비교한 것이다. 개별 응답의 정확성까지 보장하지 않으며, 문장 인코더의 선택과 정답 응답의 품질에 영향을 받는다.

## 이 논문이 풀려는 문제

지시 튜닝(instruction tuning) 모델을 비교하려면 각 지시에 대한 응답이 얼마나 적절한지 판단해야 한다. 사람이 직접 읽고 채점할 수 있지만, 모델과 그 변형이 늘어날수록 같은 지시 집합을 반복해서 평가해야 한다. 이 논문은 그 과정을 자동화할 때 **어떤 지표가 사람의 모델별 평가 결과와 가장 잘 맞는가**를 묻는다.

어휘가 겹치는 정도만으로는 응답의 적절성을 충분히 설명하기 어렵다. 논문의 Table 1은 무사히 도착한 사람에게 건네는 말을 예로 든다. 정답과 모델 응답은 서로 다른 표현을 사용하지만 같은 상황에 어울린다. 사람은 모델 응답에 최고 등급인 A를 줬으나, 보고된 점수는 ROUGE-L 0.143, BLEU 6.57이다.

이 사례는 **정답이 하나일 때 어휘 중복만으로 타당한 다른 표현을 포착하기 어려울 수 있음**을 보여준다. 논문이 제시하는 평가상의 어려움은 다음과 같다.

1. BLEU와 ROUGE-L 같은 지표는 어휘의 겹침에 기대므로, 여러 정답 응답이 있으면 다양한 타당한 표현을 포착하기 쉽다. 그러나 지시 튜닝 데이터에는 지시당 정답 응답이 보통 하나뿐이다.
2. 데이터에는 코드 작성처럼 자연어 어휘 중복이나 단어별 임베딩만으로 평가하기 어려운 지시도 섞여 있다.
3. 이미 여러 자동 평가 지표가 있지만, 이 설정에서 어느 지표가 사람의 판단과 가장 잘 맞는지 분명하지 않다.

SEMSCORE는 표현의 다양성을 다루기 위해 문장 전체의 의미 표현을 비교한다. 저자들은 이 지표와 기존 지표들을 같은 인간 평가 기준에 대조한다. 다만 코드의 기능적 정확성과 같은 문제까지 문장 유사도로 판단할 수 있는지는 별도의 검토가 필요하다.

기존 방법과 비교하면 SEMSCORE의 위치가 분명해진다. BLEU·ROUGE-L은 어휘 중복을 보고, BERTScore는 토큰 임베딩을 비교한다. BARTScore는 사전 학습 모델의 조건부 로그 확률을 사용하며, G-Eval은 언어모델에 평가 기준을 제시해 응답을 채점하게 한다. SEMSCORE는 **응답 전체를 하나의 벡터로 표현했을 때 정답 응답과 방향이 얼마나 가까운가**를 평가의 기준으로 삼는다.

## 비교의 기준: 사람은 무엇을 평가했나

저자들은 Wang 등의 Self-Instruct 연구에서 제공한 지시 252개를 사용한다. 이 지시들은 요약·분류 같은 전통적인 자연어 처리 과제에만 한정되지 않고, 글 완성, 블로그 글 제안, 코딩, 형식 논리 등 여러 용도를 포함한다.

앞선 연구가 평가한 기본 GPT-3와 그 지시 튜닝 변형 7개의 응답, 사람이 작성한 정답 응답이 제공된다. 저자들은 여기에 GPT-4, `gpt-3.5-turbo`, LLaMA, Alpaca의 응답을 더해 총 12개 모델을 비교한다.

추가한 모델 가운데 GPT-4와 GPT-3.5에는 앞선 연구와 같은 생성 설정을 적용했다. Alpaca는 공개된 코드에 따라 LLaMA의 미세조정을 재현했고, 추론에는 탐욕적 디코딩(greedy decoding)을 적용했다. 논문에는 각 모델의 구체적인 생성 매개변숫값이 모두 제시되지는 않아, 이 설명만으로 응답 생성 과정을 매개변수 수준까지 재현하기는 어렵다.

인간 평가는 A부터 D까지 네 등급이다. A가 가장 좋고 D가 가장 낮다. 저자들은 이를 각각 1부터 4까지의 점수로 바꾸어 모델별 평균을 낸 뒤 순위를 정했다. 추가 평가의 대부분은 전문가 한 사람이 맡았고, 두 번째 전문가는 생성 응답의 표본을 채점해 첫 평가를 검증했다. 부록에 보고된 평가자 간 카파(Kappa)는 0.63이다. 두 평가자는 컴퓨터과학 박사과정 학생이며, 부록에는 평가자의 연령대와 배경, 고용 계약에 따른 보상도 기재되어 있다.

인간 평가에서는 GPT-4가 가장 높고 GPT-3.5가 그다음이다. 지시 튜닝을 하지 않은 기본 GPT-3와 LLaMA는 낮게 평가됐다. 저자들은 학습 가능한 매개변수가 7B인 Alpaca의 평가 결과가 175B 매개변수의 `GPT-3Self-Inst+SuperNI` 변형과 비슷하다고도 관찰한다. 이는 이 데이터와 평가 절차에서 얻은 결과이므로, 두 모델의 일반적인 성능이 같다는 주장으로 확대할 수는 없다.

## 핵심 아이디어: 응답 하나를 벡터 하나로 비교한다

SEMSCORE는 이미 문장 표현을 만들도록 학습된 `all-mpnet-base-v2`에 모델 응답과 정답 응답을 각각 넣고, 얻은 두 벡터의 코사인 유사도를 계산한다. 논문에 따르면 이 문장 인코더는 MPNet-Base를 바탕으로 여러 영역의 문장 쌍 10억 개에 대해 대조 학습(contrastive learning)으로 미세조정됐다.

두 문자열은 독립적으로 인코딩된다. 따라서 같은 정답 응답을 여러 모델에 사용할 때 정답 쪽 임베딩을 재사용할 수 있다. 평가 대상 LLM을 다시 학습시키거나, 정답이 주어졌을 때 응답을 생성할 확률을 계산하는 과정은 필요하지 않다.

이 설계에서 코사인 유사도가 직접 비교하는 대상은 **모델 응답과 정답 응답**이다. 지시의 요구 사항은 사람이 작성하거나 검토한 정답에 간접적으로 담긴다. 따라서 정답에 드러나지 않은 제약이나, 비슷하게 서술됐지만 기능적으로 틀린 내용을 구별할 수 있는지는 별도로 확인해야 한다.

## 방법: 점수에서 모델 순위까지

### 응답별 SEMSCORE

지시를 나타내는 인덱스를 `i`, 정답 응답을 `yᵢ`, 모델 응답을 `ŷᵢ`, 문장 인코더를 `f`라고 하자. 논문의 계산을 기호로 나타내면 다음과 같다.

$$
s_i
=
\cos\!\left(f(\hat y_i), f(y_i)\right)
=
\frac{f(\hat y_i)\cdot f(y_i)}
{\lVert f(\hat y_i)\rVert_2\,\lVert f(y_i)\rVert_2}.
$$

분자는 두 임베딩의 내적이고, 분모는 두 벡터의 길이를 곱한 값이다. 두 벡터가 영벡터가 아닐 때, 이 계산은 벡터의 크기를 제거하고 **방향의 유사성**을 비교한다. 각 벡터를 길이 1로 정규화한 뒤 내적을 구해도 같은 결과를 얻는다.

코사인 유사도의 범위는 −1부터 1까지다. 논문은 1에 가까우면 의미가 유사하고 음수이면 의미가 반대라고 설명한다. 다만 음수라는 사실이 수학적으로 알려주는 것은 두 임베딩 벡터의 방향 관계다. 특정 두 문장이 논리적으로 모순되는지, 응답이 사실에 부합하는지까지 이 값 하나로 보장하지는 않는다.

이 방법의 핵심은 이미 학습된 문장 표현을 쓰고, 그 표현 사이의 코사인 유사도를 응답 품질의 대리값으로 채택한 데 있다. 따라서 인코더가 어떤 의미 차이를 크게 또는 작게 표현하는지가 평가 결과에 영향을 준다. 인코더를 바꾸면 수식이 같아도 비교하는 표현 공간은 달라진다.

### 응답별 점수를 모델별로 평균한다

모델을 나타내는 인덱스를 `m`, 지시 수를 `N`이라고 하자. 모델별 자동 평가값은 각 응답의 SEMSCORE를 평균해 구한다.

$$
\bar s_m=\frac{1}{N}\sum_{i=1}^{N}s_{m,i}.
$$

여기서 `sₘ,ᵢ`는 모델 `m`이 지시 `i`에 대해 생성한 응답의 점수이고, `s̄ₘ`은 그 모델의 전체 평균이다.

인간 평가도 A–D 등급을 1–4로 변환한 뒤 모델별로 평균한다. 두 점수의 좋은 방향은 반대다. SEMSCORE는 평균이 클수록, 인간 평가 점수는 작을수록 높은 순위다. 논문의 Table 3은 상관계수의 **절댓값**을 보고하므로, 표의 양수를 두 원점수 사이의 양의 상관으로 해석해서는 안 된다.

저자들은 켄달 순위 상관(Kendall τ)과 피어슨 상관(Pearson r)을 사용한다. 켄달 상관은 모델 쌍의 앞뒤 순서가 얼마나 일치하는지를, 피어슨 상관은 모델별 평균값 사이의 선형 관계를 살펴보는 데 쓰인다. 순서가 비슷한 것과 점수 간격까지 선형적으로 대응하는 것은 서로 다른 조건이다.

이 집계 단위가 논문의 결론을 이해하는 데 중요하다. Table 3의 높은 상관은 **모델별 평균 수준**에서 얻은 결과다. 평균 과정에서 개별 응답의 오류가 상쇄될 수 있으므로, 응답마다 사람의 등급을 잘 예측한다는 결론은 별도로 검증해야 한다.

### 무엇과 비교했나

| 계열 | 논문에서 사용한 지표와 설정 | 평가 방식 |
|---|---|---|
| 어휘 중복 | BLEU, ROUGE-L | 응답과 정답 사이의 어휘 중복을 비교한다. |
| 토큰 임베딩 | BERTScore, `deberta-xlarge-mnli` 사용 | 토큰 표현의 유사도를 비교한다. |
| 학습된 평가 모델 | BLEURT | 합성 데이터와 사람 평가 데이터의 감독 신호를 활용한 평가 모델이다. |
| 생성 확률 | BARTScore, `BARTScorepara` | 조건부 로그 확률을 사용한다. 각각 CNNDM과 ParaBank2로 미세조정한 설정을 평가한다. |
| 담화 구조 | DiscoScore의 `DS-FOCUS (NN)` | 생성 문자열의 담화 일관성에 초점을 둔다. |
| 언어모델 평가자 | G-Eval-4, G-Eval-3.5, G-Eval-3.5-instruct | 프롬프트로 언어모델에 품질 점수를 매기게 한다. |

논문은 기존 지표 8개와 SEMSCORE를 비교한다. G-Eval을 세 평가자 모델로 나누어 보고한 Table 3에는 SEMSCORE를 포함해 총 11개 설정이 등장한다.

각 방식은 확인하는 정보가 다르다. 문장 임베딩은 표현이 달라지는 문제를 완화할 수 있지만, 코드 실행이나 출력의 형식 조건을 직접 검사하지 않는다. G-Eval은 평가 프롬프트에 지시 수행 기준을 넣을 수 있으며, 대신 평가자 모델과 프롬프트 선택에 영향을 받는다. 이 비교 실험은 각 설계가 해당 인간 평가와 얼마나 잘 맞는지를 보여준다.

## 구현 관점에서: 생성과 채점을 분리하기

SEMSCORE의 핵심은 이미 생성된 응답의 채점이다. 먼저 각 모델의 응답을 수집하고, 지시마다 대응되는 정답과 응답을 인코딩해 비교한다. 다음은 계산 구조를 설명하기 위한 개념적 의사코드다.

```python
# encode_sentences: all-mpnet-base-v2로 문자열마다 벡터 하나를 반환
# 문자열 B개 입력 -> shape (B, D)

def semscore_batch(model_responses, target_vectors, encode_sentences):
    # target_vectors는 model_responses와 같은 지시 순서여야 한다.
    response_vectors = encode_sentences(model_responses)  # (B, D)

    dot = sum_over_embedding_dim(
        response_vectors * target_vectors
    )  # (B,)
    response_norm = l2_norm_over_embedding_dim(
        response_vectors
    )  # (B,)
    target_norm = l2_norm_over_embedding_dim(
        target_vectors
    )  # (B,)

    return dot / (response_norm * target_norm)  # (B,)


target_vectors = encode_sentences(targets)  # (N, D)

for model in evaluated_models:
    outputs = responses_for(model)  # targets와 같은 지시 순서
    scores = semscore_batch(
        outputs, target_vectors, encode_sentences
    )
    model_score[model] = mean(scores)

ranking = sort_models_by_descending_score(model_score)
```

`sum_over_embedding_dim`과 `l2_norm_over_embedding_dim`은 수식의 축 연산을 나타내기 위한 의사코드다. `B`는 한 번에 처리하는 문자열 수, `D`는 문장 임베딩의 차원이다. 논문은 특정 라이브러리 호출, 배치 크기, 토큰 길이 제한, 정규화 API를 제시하지 않는다.

실제 구현에서는 인코더가 문장마다 `(D,)` 형태의 벡터 하나를 반환하는지 확인해야 한다. 길이 `L`인 입력의 토큰별 `(L, D)` 표현을 풀링 없이 그대로 비교하면 문장 임베딩 간 코사인 유사도와 다른 계산이 된다.

정답 임베딩을 미리 계산하는 부분은 독립 인코딩 구조에서 도출한 구현상의 최적화다. 동일한 지시와 정답 집합으로 여러 모델을 평가할 때 재사용할 수 있다. 인코더나 전처리, 정답 응답이 바뀌면 해당 임베딩도 다시 계산해야 한다. 논문은 이 캐시를 사용했는지나 절감된 시간을 보고하지 않는다.

재현 구현에서는 다음 경계를 확인할 필요가 있다.

- **정답과 응답의 대응:** 두 목록은 같은 지시 순서여야 한다. 개수가 같더라도 순서가 어긋나면 코사인 연산은 정상적으로 끝나면서 잘못된 쌍을 비교한다.
- **평균의 비교 대상:** 모델마다 누락된 응답이 다르면 서로 다른 지시 집합의 평균을 비교하게 된다. 누락 처리 방식을 먼저 정해야 한다.
- **점수의 방향:** SEMSCORE는 클수록, 인간의 1–4 점수는 작을수록 좋다.
- **인코더의 식별:** 권장 설정은 `all-mpnet-base-v2`다. 다른 인코더를 쓰면 평가 설정이 달라진다.
- **수치적 경계:** 두 임베딩의 차원이 같아야 하며, 코사인 계산에서 영벡터로 나누는 경우를 확인해야 한다. 논문은 영벡터 처리 규칙을 별도로 보고하지 않았다.
- **점수의 해석:** 코사인 유사도를 A–D 등급이나 정답률로 바꾸는 임곗값은 제시되지 않았다.

이 점검 항목들은 논문의 계산을 구현할 때 필요한 검토 사항이다. 논문에서 별도의 처리 규칙이나 검증 절차로 제안한 것은 아니다.

## 비용과 트레이드오프

SEMSCORE의 계산은 문장 인코딩과 코사인 유사도 계산으로 나뉜다. 코사인 연산량은 임베딩 차원에 따라 늘고, 문장 인코딩에는 기반 모델의 추론이 필요하다. 논문에는 처리량, GPU 시간 또는 단계별 실행 시간 측정이 없으므로 실제 병목이나 속도 비율을 정량적으로 말하기는 어렵다.

독립 인코딩은 정답 임베딩을 재사용할 여지를 준다. 여러 모델이 같은 지시와 정답 집합을 공유하면, 정답은 한 번 인코딩하고 각 모델의 응답만 새로 인코딩할 수 있다. 이는 계산 구조에서 도출되는 최적화이며, 실제 절감률은 배치 구성과 문장 길이, 장치에 따라 달라진다. 정답 벡터를 보관하는 저장 공간도 필요하다.

경량화 관점에서 논문이 직접 제공하는 근거는 기반 모델의 규모와 상관 결과다. 기본 SEMSCORE의 인코더는 BERTScore에 사용한 인코더보다 층 수와 은닉 크기가 작으면서도 높은 상관을 얻었다. 한편 같은 DeBERTa를 사용한 실험에서는 풀링 방식에 따라 결과가 달라졌다. 이 결과는 평가 모델의 크기와 함께 **문장 표현에 맞는 학습 및 풀링 방식**을 살펴봐야 함을 보여준다.

G-Eval은 평가용 언어모델에 접근하고 프롬프트를 구성해야 한다. 저자들은 SEMSCORE가 이런 평가자 접근에 의존하지 않는다는 점을 재현성과 비용 측면의 장점으로 제시한다. 다만 문장 인코더를 실행하는 계산 비용은 여전히 존재하며, 논문은 금전 비용이나 전체 GPU 사용량을 실측해 비교하지 않았다.

계산이 단순한 만큼 점수가 표현하는 정보도 제한된다. SEMSCORE는 정답과 응답의 문장 유사도를 반환한다. 코드가 실행되는지, 사실이 맞는지, 요구된 항목만 포함했는지 확인하는 별도의 검사 과정은 없다. 부록의 코드와 장르 사례는 이 경계를 보여준다.

여기서 도출되는 후속 질문은 모델별 비교에 유용한 상관을 유지하면서 개별 응답의 제약 위반을 어떻게 더 잘 잡을 수 있는가이다. 추가 검사의 계산 비용과 필요한 평가 자원까지 함께 비교해야 하지만, 이 논문은 그 후속 설계의 성과까지 측정하지는 않는다.

## 이 논문이 놓인 흐름

이 연구는 어휘 중복, 학습된 표현, 언어모델 평가자를 이용하는 여러 평가 접근을 같은 인간 평가에 대조한다. SEMSCORE의 기여는 **문장 수준 의미 유사도를 지시 응답 평가에 직접 적용하고 그 유효성을 비교 실험으로 확인한 것**에 있다.

관련 연구 논의에서 저자들은 언어모델 평가가 프롬프트 선택에 영향을 받고 위치 편향을 보일 수 있다는 선행 결과를 짚는다. GPT-4 같은 독점 모델을 평가자로 쓰면 접근 가능성과 모델 업데이트가 재현성에도 영향을 줄 수 있다고 설명한다.

SEMSCORE는 평가에 사용할 인코더를 명시할 수 있다. 이 장점을 살리려면 인코더의 이름과 설정을 결과와 함께 보존해야 한다. 인코더를 바꾸면 점수의 의미와 모델 순위도 달라질 수 있기 때문이다.

다른 언어, 이미지가 포함된 요청, 더 긴 대화에서도 같은 상관이 유지되는지는 이 논문의 실험으로 판단할 수 없다. 다양한 텍스트 지시를 포함한 데이터에서 얻은 결과라는 범위를 유지해 읽어야 한다.

## 한계와 생각해볼 점

저자들이 밝힌 첫 번째 한계는 **기반 문장 인코더에 대한 의존**이다. 다른 STS 모델을 쓰면 유사도와 최종 순위가 달라질 수 있다. 저자들은 SEMSCORE를 보고할 때 `all-mpnet-base-v2`를 사용하거나, 다른 모델을 썼다면 그 이름을 명시하라고 권한다. Table 4의 결과도 인코더와 문장 표현 방식이 평가의 일부임을 보여준다.

두 번째 한계는 **정답 응답의 필요성**이다. SEMSCORE에는 대조할 정답 응답이 적어도 하나 필요하며, 저자들은 사람이 작성했거나 사람의 검토를 거친 정답을 요구한다. 정답이 하나뿐이라면 타당한 다른 답이 그 정답과 멀게 표현될 위험이 있다. 의미 유사도를 사용해도 정답의 대표성 문제가 사라지지는 않는다.

이 조건을 비교한 모든 지표에 동일하게 적용해서는 안 된다. 부록 A.3에 제시된 G-Eval 프롬프트의 입력은 지시문과 모델 출력이며, 정답 응답을 넣는 항목은 없다. 이 프롬프트는 전반적 품질을 다음 기준으로 채점하도록 한다.

| 점수 | 평가 기준 |
|---|---|
| 1 | 지시를 충족하고 불필요한 반복이나 무관한 부분이 없는 유효한 응답 |
| 2 | 작은 오류나 불완전함이 있지만 수용 가능한 응답 |
| 3 | 지시와 관련은 있지만 내용에 중대한 오류가 있는 응답 |
| 4 | 지시와 무관하거나 완전히 무효한 응답 |

G-Eval은 지시 수행 여부를 직접 평가하도록 요청받고, SEMSCORE는 정답과 응답의 의미 유사도를 계산한다. Table 6은 두 방식 모두 개별 사례에서 잘못된 평가를 할 수 있음을 보여준다.

세 번째 한계는 **평가 데이터의 규모와 구성**이다. 데이터는 지시 252개로 작고 전통적인 NLP 과제에 초점을 맞추지 않는다. 저자들은 다양한 실제 텍스트 지시를 담았다는 점에서 이 구성이 지시 튜닝 모델 평가에 현실적이라고 주장한다.

실험이 뒷받침하는 결론은 이 데이터와 인간 평가 절차에서 SEMSCORE의 모델별 평균이 높은 상관을 보였다는 것이다. 개별 응답의 합격 여부, 코드의 기능적 정확성, 특정 제약의 충족 여부를 평가하려면 해당 실패 유형에 대한 검증이 추가로 필요하다.

## SKALA 교안과 대조한 부분

SKALA RAG 교안 PDF 149·154쪽은 SemScore를 LLM 기반 평가와 LLM-as-a-Judge의 흐름에서 설명한다. 그러나 원논문의 SEMSCORE 점수는 **문장 인코더가 만든 임베딩의 코사인 유사도**로 계산한다. 평가자가 된 LLM에 채점 프롬프트를 보내는 방식과는 계산 절차가 다르다. 교안 154쪽은 기계 번역과 요약 평가에도 쓰인다고 설명하지만, 이 논문에서 인간 평가와의 상관을 측정한 대상은 instruction-tuned LLM의 응답이다. 다른 과제에 적용할 수 있는지는 그 과제의 정답과 인간 평가를 갖춰 다시 검증해야 한다.

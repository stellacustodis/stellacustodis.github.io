SKALA 부트캠프의 **스마트 데이터 이해 및 활용** 과정은 데이터베이스의 구조를 이해하는 데서 시작해 SQL 작성, 성능 최적화, Cloud DB 운영까지 이어지는 4일 과정이다.

학부에서 데이터베이스 강의를 수강했었지만 해당 강의에서는 굉장히 **기초적인**내용만 다루었었고 나 역시 그리 깊게 공부를 하지 않았어서 두루뭉실하게 몇몇 키워드 중심으로 아는게 전부였다. SKALA 부트캠프에서의 **스마트 데이터 이해 및 활용** 과정에서는 실무 중심의 데이터베이스를 배울 수 있었다. 비전공자 입장에서는 굉장히 따라가기 힘들었고 '이렇게 까지 깊게 공부를 해야 하나?'라는 질문이 수업 내내 따라다녔지만, 그럼에도 본 일정이 전체 교육과정에서 4일이나 할애한다는 것은 분명 이유가 있을 것이라 생각해서 최대한 내용을 정리해 본다.


이 시리즈에서는 강의 내용을 그대로 옮기기보다 다음 세 가지 질문을 중심으로 정리한다.

1. 오늘 배운 개념은 무엇인가?
2. 이 개념은 왜 필요한가?
3. 실제 SQL과 시스템에서는 어떻게 사용되는가?

> 강의자료는 개념을 이해하기 위한 참고 자료로만 활용하고, 글의 설명과 예시는 직접 재구성했다.
{: .prompt-info }

## 전체 흐름

| 일차 | 핵심 주제 | 도달 목표 |
|---|---|---|
| 1일차 | 관계형 모델, ERD, 스키마, DDL/DML | 요구사항을 테이블 구조로 표현한다 |
| 2일차 | JOIN, 서브쿼리, CTE, View, Window Function | 여러 테이블에서 필요한 결과를 정확히 조회한다 |
| 3일차 | 인덱스, 실행 계획, SQL 튜닝, Lock | 느린 쿼리의 원인을 찾고 개선한다 |
| 4일차 | Procedure, Trigger, Cloud·분산 DB, Trend, 보안·백업·모니터링 | 애플리케이션 밖의 DB 처리와 운영 관점을 이해한다 |

각 날짜는 독립된 주제처럼 보이지만 실제로는 하나의 흐름이다.

```text
요구사항
  → 데이터 모델과 ERD
  → 테이블과 제약조건
  → SQL로 조회·변경
  → 실행 계획과 인덱스로 최적화
  → 권한·백업·모니터링을 포함한 운영
```

좋은 SQL도 잘못 설계된 테이블 위에서는 한계가 있고, 잘 설계된 데이터베이스도 운영과 복구 계획이 없으면 신뢰할 수 없다. 그래서 이번 과정은 단순히 SQL 문법을 외우는 수업이라기보다 **데이터의 생애주기 전체를 보는 연습**에 가깝다.

## 실습 환경

과정에서는 PostgreSQL과 DBeaver를 사용한다. Mac에서 해당 프로그램들을 사용하는 것이 공식적인 교육이었지만, 나는 ubuntu에 두 프로그램을 따로 설치해서 따라갔다. 또 두 프로그램들이 익숙치는 않아서 vscode에 extension을 설치하여 쿼리를 작성하는 방식을 택하였다.

- **PostgreSQL**: 데이터를 저장하고 SQL을 실행하는 관계형 DBMS
- **DBeaver**: DB 접속, SQL 작성, 결과 확인을 돕는 GUI 클라이언트

DBeaver 자체가 데이터베이스인 것은 아니다. DBeaver에서 작성한 SQL을 PostgreSQL 서버에 전달하고, 서버가 돌려준 결과를 화면에 보여주는 구조다.

```text
사용자 → DBeaver → PostgreSQL → 데이터 파일
```

이 둘의 역할을 구분하면 접속 오류, SQL 오류, 서버 오류를 나누어 생각하기 쉬워진다.

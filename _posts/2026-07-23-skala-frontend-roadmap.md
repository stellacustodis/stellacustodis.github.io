SKALA 부트캠프의 **Full-Stack Engineering — HTML, CSS, JavaScript** 과정은 웹이 어떤 원리로 동작하는지 이해하는 데서 출발해, 문서의 구조를 만들고(HTML), 그 구조에 표현을 입히고(CSS), 마지막으로 동작을 부여하는(JavaScript) 순서로 진행되는 2일 과정이다.

AI 엔지니어를 목표로 하는 입장에서 프론트엔드 과정은 언뜻 우선순위가 낮아 보인다. 하지만 실제로 모델을 만들고 나면 그 결과를 **누군가에게 보여줘야 하는 순간**이 반드시 온다. 추론 결과를 확인하는 데모 페이지, 실험 로그를 비교하는 간단한 대시보드, 학습 파이프라인 상태를 보여주는 모니터링 화면 같은 것들이다. 이때 필요한 것은 화려한 프레임워크가 아니라 **HTTP 요청이 어떻게 오가고, DOM이 어떻게 갱신되며, 비동기 호출이 어떤 순서로 처리되는지**에 대한 감각이다. 이번 과정은 그 감각의 바닥을 만드는 시간에 가깝다.

이 시리즈에서는 강의 내용을 그대로 옮기기보다 다음 세 가지 질문을 중심으로 정리한다.

1. 오늘 배운 개념은 무엇인가?
2. 이 개념은 왜 필요한가?
3. 실제 코드에서는 어떻게 사용되는가?

> 강의자료는 개념을 이해하기 위한 참고 자료로만 활용하고, 글의 설명과 예시 코드는 직접 재구성했다.
{: .prompt-info }

## 전체 흐름

| 일차 | 핵심 주제 | 도달 목표 |
|---|---|---|
| 1일차 | 웹 동작 원리, HTML 기초·Form·심화 | 문서의 **구조와 의미**를 마크업으로 표현한다 |
| 2일차 | CSS 기초·심화, JavaScript 기초·심화 | 구조에 **표현**을 입히고 **동작**을 부여한다 |

두 날은 별개의 주제처럼 보이지만 실제로는 하나의 계층 구조다. 웹 페이지는 아래 세 축이 역할을 나눠 갖는다.

```text
HTML  →  구조(Structure)   : 무엇이 있는가
CSS   →  표현(Presentation): 어떻게 보이는가
JS    →  동작(Behavior)    : 어떻게 반응하는가
```

이 분리는 미학적 취향이 아니라 유지보수의 문제다. 구조와 표현이 뒤섞이면 디자인 하나를 바꾸는 데 마크업 전체를 건드려야 하고, 구조와 동작이 뒤섞이면 이벤트 하나를 추적하는 데 HTML을 뒤져야 한다. 과정 내내 "왜 인라인 스타일 대신 외부 CSS인가", "왜 `onclick` 속성 대신 `addEventListener`인가" 같은 질문이 반복되는데, 답은 결국 이 관심사 분리로 수렴한다.

전체 흐름을 조금 더 풀어 쓰면 다음과 같다.

```text
브라우저에 URL 입력
  → DNS 조회, TCP 연결, HTTP 요청/응답
  → HTML 파싱 → DOM 트리 구성
  → CSS 적용 → 레이아웃 계산 → 렌더링
  → JS가 DOM을 조작하고 이벤트에 반응
  → 필요하면 fetch로 서버와 비동기 통신
```

1일차는 이 흐름의 앞부분(요청·응답과 DOM의 재료가 되는 HTML)을, 2일차는 뒷부분(렌더링과 동적 제어)을 다룬다.

## 왜 이 순서인가

과정의 순서는 [roadmap.sh의 프론트엔드 입문 경로](https://roadmap.sh/frontend-beginner)와 같은 뼈대를 따른다. HTML → CSS → JavaScript를 먼저 다지고, 그다음에 Git·npm·React 같은 도구와 프레임워크로 넘어가는 구조다.

이 순서가 중요한 이유는, 프레임워크가 결국 이 세 가지를 추상화한 결과물이기 때문이다. React의 가상 DOM을 이해하려면 진짜 DOM이 무엇인지 알아야 하고, 컴포넌트의 상태 갱신을 이해하려면 브라우저가 언제 리렌더링하는지 알아야 한다. 바닥을 건너뛰면 프레임워크가 예상과 다르게 동작할 때 디버깅할 근거가 없다.

## 실습 환경

과정에서는 별도의 빌드 도구 없이 **VS Code + Live Server** 조합만 사용한다.

- **VS Code**: 편집기
- **Live Server (확장 프로그램)**: 로컬 개발 서버. 파일을 저장하면 브라우저가 자동으로 새로고침된다
- **Emmet**: VS Code에 내장된 코드 자동완성 엔진. `.html` 파일에서 `!`를 입력하면 HTML5 뼈대가 생성된다
- **브라우저 개발자 도구**: `F12` 또는 `Ctrl + Shift + I`. Elements/Console/Network 탭을 계속 사용한다

번들러나 트랜스파일러를 쓰지 않는 것은 의도적인 선택으로 보인다. 도구가 개입하지 않아야 **브라우저가 파일을 어떻게 해석하는지**가 그대로 드러나기 때문이다.

> Live Server는 `file://`이 아니라 `http://127.0.0.1:5500` 같은 주소로 페이지를 연다. `fetch`나 ES 모듈처럼 출처(origin) 개념이 필요한 기능은 `file://`에서 동작하지 않으므로, 개발 서버를 쓰는 것이 필수에 가깝다.
{: .prompt-tip }

## 글을 정리하는 기준

각 일차의 글은 다음 순서를 기본으로 한다.

- 그날의 핵심 질문
- 꼭 알아야 할 개념과 그 개념이 필요한 이유
- 직접 실행해 볼 수 있는 최소 예제 코드
- 자주 헷갈리는 지점
- 정리와 남은 질문

과정에는 개인 실습 과제와 종합실습(중고차 목록 관리 CRUD 화면 구현)이 포함되어 있지만, 이 시리즈에서는 **강의에서 다룬 개념 정리에 집중**하고 과제 결과물은 다루지 않는다.

첫 번째 글에서는 인터넷과 웹의 차이에서 출발해 HTTP 요청·응답 구조, HTML 문서의 구성, 시맨틱 마크업과 접근성까지 연결한다.
